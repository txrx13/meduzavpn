# MeduzaVPN 1.2.44 (256)

Android (APK from the website), Windows (installer and command line), the macOS app (DMG), Linux (packages, archives and the apt/dnf repositories), routers and OpenWrt are updated to build 256, all from the same published application main revision. The macOS DMG is built on Apple hardware. The macOS command line is not part of this publication and keeps its own version below. Store channels (App Store, TestFlight, Google Play) are not changed by this publication.

## Changes since 249

- **ULTRA connects faster and holds up better.** Pipelined SSH authentication for ULTRA/1 and ULTRA/2 carriers; a carrier is in service with its first session; ULTRA/2 standby carrier with a racing dialer, 8 carriers on desktop and 4 on phones; the core reports a per-stage connect timeline.
- **Split downloads no longer freeze.** On an ULTRA/2 split (entry → exit) a chunk dropped by the receiver is sent again instead of stalling the stream.
- **Datagram traffic survives an outage.** The backlog a carrier flushes after a blackout is kept, and one retransmission timeout no longer counts as a stall.
- **Split tunneling switch fixed.** Turning split tunneling on in a VPN's settings no longer sends every unmatched site past the VPN: OTHERS follows the entry VPN unless you choose otherwise, a Direct OTHERS shows a warning, and the connection check names this case.
- **Signed ULTRA profile is cached** and its revision checked in the background, so a connect no longer re-enrolls every time.
- **Faster start from Russia.** The app adopts the first API origin that answers instead of waiting for a silent one, and opens the website the server chooses (meduzacore.com for Russia).
- **Location picker.** The chosen location is listed first and outlined; the "Recommended" badge no longer looks like the selection; no "Works from Russia" badge on Russia itself.
- **Connect On Demand** starts the tunnel on the VPN you picked rather than a previously stored one.
- **Notifications** permission is asked again at a moment of value, with the app's own explanation first.

## Installation

Install **either** `meduzavpn-desktop` for the graphical application (daemon included) **or** `meduzavpn` for a headless CLI/service installation. Use the [signed apt/dnf instructions](../README.md#install-on-linux). Windows: [meduzavpn.com/download/windows](https://meduzavpn.com/download/windows). Android: [meduzavpn.com/download/android](https://meduzavpn.com/download/android).

## Verification and limits

- **Source:** every artefact was built from `002669d4` (verified on main before and after each build step); version strings inside the artefacts read 1.2.44 / 256.
- **Android:** APK signed with the release certificate (CN=Meduza VPN, `apksigner verify`), versionCode 256 / versionName 1.2.44, ULTRA signing root present in the app library.
- **Windows:** installer, app and ULTRA engine signed (Authenticode, IPFB LLC, timestamped). The ULTRA engine (`ultra_core.dll`) was rebuilt from the 256 source; `windows/UltraCoreGo` at this revision lacks the patched x/crypto replace, so the DLL was built with an out-of-tree module file adding exactly the replace the core module declares (fix for the next build: branch `cl/fix-ultracorego-xcrypto`). Silent install on Windows 11 in the build VM: exit 0, installed version 1.2.44+256, installed signatures valid, installed engine identical to the rebuilt one, the app starts and responds.
- **Linux:** packages carry the ULTRA signing roots in `meduzavpnd`; installed from the local files on Ubuntu 24.04, Debian 13 and CentOS Stream 9 (desktop and core separately), no missing libraries, the GUI starts under Xvfb. The repository's systemd end-to-end test on Ubuntu 22.04/24.04, Debian 12, CentOS Stream 9 and Fedora 41: 179 checks passed, 21 failed — the same 21 "after upgrade to core" expectations as build 249 (the harness still expects desktop behaviour after the core package explicitly replaces the desktop one). RPMs and repository metadata are signed.
- **Routers / OpenWrt:** four static daemon archives (mips, mipsle, arm, arm64) report 1.2.44+256 under emulation and pass the ULTRA signer tests; three OpenWrt packages carry the production ULTRA key and not the lab key; the x86-64 package passes the repository's install test in an OpenWrt 24.10.8 userland.
- **Command line:** `cli/check.sh` at this revision stops at a stale path (fixed on the same branch); every step before it passed and the corrected remaining steps pass.
- **macOS:** the DMG is built, signed and notarized on Apple hardware; here it was only checked for size, SHA-256 and recorded source revision.
- **Not covered here:** live VPN traffic tests on Windows and Android run separately.
