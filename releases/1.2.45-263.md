# MeduzaVPN 1.2.45 (263)

Android (APK from the website), Windows (installer and command line), macOS (DMG), Linux (packages, archives and the apt/dnf repositories), routers and OpenWrt are updated to build 263, all from the same published application main revision, after a connection test of every protocol mode on Android, Windows and Linux. The macOS DMG is built, signed and notarized on Apple hardware; the macOS command line is not part of this publication and keeps its own version below. Store channels are not changed by this publication.

## Changes since 256

- **ULTRA on Windows connects much faster.** The tunnel adapter is configured through the IP helper and no DNS step waits for validation any more (was 17–23 s per connect).
- **ULTRA on x86_64 Android devices.** The APK now carries the ULTRA engine for x86_64 as well as ARM (emulators, some Chromebooks and tablets).
- **ULTRA/2 learns a node's dead IPv6** from the tunnel instead of retrying it on every carrier; split tunnels stop promptly during a switch and say when one exit location is out.
- **Connect errors are named** (timeout at the location, native start failure, sign-in problems) instead of "check your internet"; ULTRA recovers from an expired session token.
- **Backup DNS resolvers** (Quad9, Yandex) after the primary one, in the order the node measured.
- **Restart VPN** in a VPN's settings (owner only), reachable through the backup API; home, VPN list and settings show the running operation (restart, redeploy, reinstall, move, IP change) with a countdown instead of "not responding".
- **"Update available" banner** that sends each install to its own update source (store, website APK, desktop installer).
- **Android: "Apps without VPN"** in Settings, with a warning when a choice would switch the protocol.
- **ULTRA diagnostics** sheet shows the right protocol for the current session and can send its journal to Mia.
- **Your VPN's label** from the website is shown in the app; owners of a shared VPN see how busy it is.
- **Wording:** customer texts say VPN and IP, not "server", in all 12 languages.
- **Checkout** asks before ordering or moving to a location that is closed from Russia; store purchases that are queued or refused are handled and named; order reminders from What's new get their finish button.

## Installation

Install **either** `meduzavpn-desktop` for the graphical application (daemon included) **or** `meduzavpn` for a headless CLI/service installation. Use the [signed apt/dnf instructions](../README.md#install-on-linux). Windows: [meduzavpn.com/download/windows](https://meduzavpn.com/download/windows). Android: [meduzavpn.com/download/android](https://meduzavpn.com/download/android).

## Verification and limits

- **Source:** every artefact was built from `71e3c354` (checked on main before and after each build step). Version strings inside the artefacts read 1.2.45 / 263.
- **Connection test gate (before publication):** on toxa, with lab accounts only, the published Android APK, Windows installer and Linux package connected in all three modes (hybrid, ULTRA/2 only, ULTRA/1 only) to a single location and through a split (Helsinki → Frankfurt): 18/18 PASS. Each run checked the exit IP, DNS, a download, and disconnect/reconnect; the mode was confirmed by the protocol in the journal and by the carrier count. Windows reaches the first HTTPS reply in 6–7 s (was 20–28 s in 256).
- **Android:** APK signed with the release certificate (CN=Meduza VPN), versionCode 263 / versionName 1.2.45, the ULTRA engine present for arm64-v8a, armeabi-v7a and x86_64, and the ULTRA signing root in the app.
- **Windows:** installer, app and ULTRA engine are Authenticode-signed (IPFB LLC, timestamped), and the ULTRA engine is rebuilt from source. A silent install in the build VM installs 1.2.45+263 with valid signatures, and the app starts.
- **Linux:** the ULTRA signing roots are in `meduzavpnd`. Installed from the local files on Ubuntu 24.04, Debian 13 and CentOS Stream 9, the GUI starts. The repository's systemd end-to-end test: 179 passed and 21 failed, the same 21 "after upgrade to core" harness expectations as 249 and 256. RPMs and repository metadata are signed, and installs from the public apt/dnf repositories are checked on Ubuntu, Debian, CentOS and Fedora.
- **Routers / OpenWrt:** four static daemon archives report 1.2.45+263 under emulation and pass the ULTRA signer tests. The OpenWrt packages carry the production ULTRA key, and the x86-64 package passes the install test in an OpenWrt 24.10.8 userland.
- **macOS:** the DMG is built, signed, notarized and stapled on Apple hardware. The macOS command line is not part of this publication.
