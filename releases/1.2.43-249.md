# MeduzaVPN 1.2.43 (249)

All direct-download applications, CLI tools, Linux packages and router packages are updated to build 249 from the same published application main revision. iOS and macOS 249 are available to the existing internal TestFlight group. Public App Store, Google Play and tvOS releases are unchanged by this publication.

## Changes

- The Linux/OpenWrt ULTRA daemon now finishes DNS and route cleanup before exiting. Restarting the service no longer leaves the next connection using a stopped tunnel's DNS resolver.
- Linux standalone desktop packages include their daemon, enable the desktop service and support access from a local login session. Headless packages remain disabled until explicitly started.
- Includes the accumulated Windows ULTRA routing, reconnect, DNS and uninstall fixes, connection-status handling and protocol-picker layout correction already merged into main.

## Installation

Install **either** `meduzavpn-desktop` for the graphical application (daemon included) **or** `meduzavpn` for a headless CLI/service installation. Installing core explicitly replaces a standalone desktop package. Use the [signed apt/dnf instructions](../README.md#install-on-linux).

## Verification and limits

Release binaries are signed where supported; the macOS DMG and universal CLI are notarized. Final OpenWrt 249 passed real ULTRA traffic, three 25 MB downloads, 20 pings with zero loss, and five stop/start cycles checking DNS/routes restoration. The LuCI Restart action reconnected successfully. Linux installation, reboot, local-session access and desktop upgrades were exercised on five distributions; a separate check passed the explicit standalone-desktop-to-core replacement path on three Debian-family distributions. The original harness still expected desktop behavior after core replacement and recorded those expectation failures. CLI/core unit and race tests and Android native unit tests passed. Windows 249 installed successfully with a valid signature.

Full Flutter tests on Linux: 1671 passed, 11 skipped, 6 platform-dependent notification/badge failures. Those focused tests passed on macOS for the preceding application revision; they are not represented as a fully green 249 suite. Final Windows/macOS GUI and physical Apple-device testing are not complete. The owner is testing the Apple builds. ARM/MIPS checks use compilation/emulation rather than every physical router model. Artificially throttled Android TV testing remained inconclusive because the non-VPN control also stalled.
