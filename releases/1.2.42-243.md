# MeduzaVPN 1.2.42 (243) — Windows update

A Windows-only update of the graphical app. Every other platform stays at **[1.2.42 (242)](1.2.42-242.md)**.

## What changed

- **ULTRA now always captures the whole system's traffic.** The tunnel installs two half-routes (`0.0.0.0/1`, `128.0.0.0/1`), which win over the internet provider's route by prefix length, not by metric. Before, modem software or another program with a lower route metric could keep the browser on the direct connection while the app showed "connected".
- **No more false "connected".** After the tunnel comes up, the app checks that the system's best route really leads into the MeduzaVPN adapter. If another program holds the routes, the connection is refused with a plain explanation: close that program and connect again.
- **The connection check notices a leak.** It compares the exit address with the VPN server and with the address seen without the VPN, and asks Windows where its traffic goes. The report now has `exit`, `leak` and `routes` lines. The new verdict is "The VPN is connected, but traffic is bypassing it".
- The adapter is configured by its interface index, after its network interface exists. Server exception routes also work on dial-up (PPP) connections.
- The ULTRA engine for Windows is rebuilt from the current core: carrier recovery, delayed-frame handling and memory fixes that the other platforms already had.
